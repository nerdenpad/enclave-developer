# NEAR Gateway release path

NEAR remains the selected GPU inference provider. The application gateway, website and Arc worker can run on the existing server. NEAR evidence is verified for the remote inference path; application request encryption terminates at our gateway.

The hosted route uses experimental direct `*.completions.near.ai` verification, selected explicitly through `NEAR_ENDPOINT_PROFILE=direct-experimental`. Reviewed provider policy v6 passed new paid EOA acceptance and production startup on 4 October 2026; see [release progress](../../docs/release-progress.md) for the dated evidence, expiry and remaining E1 checks. NEAR documents direct verification as experimental and recommends `cloud-api.near.ai` for new production verification workflows. Selecting the direct route does not guarantee future availability.

The separate `near-verified` Cloud Gateway route uses `INFERENCE_BASE_URL=https://cloud-api.near.ai/v1` and `NEAR_ENDPOINT_PROFILE=cloud`. Before each prompt it requests a fresh Gateway report and all model candidates, verifies the Gateway and every candidate against a versioned policy, pins the Gateway TLS key on the reused connection, and requires a `provider_tee` response signature from exactly one verified model signer. A `gateway` signature alone does not prove model-level response binding. Changing the hosted route requires a matching reviewed policy and accepted release archive.

Before release, review and version the accepted measurements and image provenance. The Gateway policy file uses the existing `profiles` list for model candidates and a separate `gatewayProfiles` list. Each Gateway profile contains `appComposeSha256` and a complete `measurements` map; the verifier never learns or approves a new profile from a live report. The local CLI accepts the combined preflight document on stdin with `python infra/near/verify.py --cloud --policy <reviewed-policy.json>`. A `--gateway` mode checks only the Gateway profile. Reject missing model candidates, unapproved measurements, expired evidence, absent or ambiguous signatures and changed TLS peers. Persist the exact verification evidence with the encrypted transcript and receipt reference. The existing development policy is not a reviewed Gateway release policy.

For a new deployment or route, register and approve the selected model, application code and policy binding in Arc ModelRegistry. Test one hosted inference, signed receipt and confirmed Arc anchor; verify restart and retry recovery. Enable public payments only after a separately approved small real-USDC acceptance test passes without duplicate settlement or execution. The hosted direct deployment has completed paid backend acceptance; physical OKX and remaining E1 operational acceptance are tracked separately.

`npm run registry:prepare:arc -- --model MODEL_ID --code-hash 0x... --policy-hash 0x... --policy-version N` performs a read-only Arc preflight against the ignored `.local/arc-deployment.json` record. It checks the reviewed registry owner and stake token, duplicate listings, the provider's one-ENCL stake and gas balance, then prints exact wallet transaction requests. It never loads private keys, signs or broadcasts. Use only final reviewed release hashes. The registry owner must separately approve the confirmed listing after its one-hour timelock; local bootstrap approval is unavailable on Arc Mainnet.

The production configuration must require the verified NEAR path, Arc network and user authentication, and must reject echo or local-test settings. The public status and receipt UI should describe only evidence established by the deployed path.

Official references: [NEAR Gateway verification](https://docs.near.ai/cloud/verification/cloud-api), [direct completions limitations](https://docs.near.ai/cloud/experimental/direct-completions), and [Arc network parameters](https://docs.arc.io/arc/references/connect-to-arc).
