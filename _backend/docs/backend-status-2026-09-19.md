## Подтверждённый живой сценарий

В 17:09:38 UTC завершён один реальный запрос к `z-ai/glm-5.3-flash` в NEAR:

- свежая криптографическая проверка Intel TDX и NVIDIA для восьми GPU;
- актуальный TCB, допустимый полный профиль VM, привязка к фактическому TLS-ключу;
- проверка подписи точных байтов запроса/ответа и связи с локальной квитанцией;
- зашифрованные запрос, ответ и полный transcript;
- сохранение в PostgreSQL и идентичный ответ после перезапуска без второй генерации;
- экспорт квитанции по view-key;
- оплата тестовым USDC и реальная запись квитанции в контракт временного Anvil.

Лимит генерации — 32 токена. Время сценария — 14,4 секунды. Секреты и текст ответа не записаны в отчёт. Подтверждающие хеши и флаги: [JSON результата](evidence/near-live-2026-09-19.json).

Это проверка управляемого GPU-провайдера вместе с локальным стеком. Она не подтверждает размещение шлюза в TEE, платежи реальным USDC в Arc или конфиденциальность блокчейн-переводов.

## Требования и границы

| Требование | Реализовано / проверено | Что остаётся |
|---|---|---|
| Composite CPU + GPU attestation | Настоящие Intel DCAP и NVIDIA ES384-подписи, свежий nonce, строгий TCB, проверка каждой GPU | Собственная измеренная среда ENCLAVE и выдача её ключей только внутри TEE |
| Измеренный workload и TLS | TLS связан с аппаратной цитатой; два полных профиля NEAR, журнал manager и pinned-конфигурация | Журнал NEAR не доказывает все runtime override и текущий бинарник manager; проверка байтов весов и воспроизводимой сборки не выполнена |
| Подписанные квитанции | EIP-712 v2; отдельная подписанная связь с evidence NEAR; зашифрованный transcript; Anvil anchoring | Локальный signer пока программный; аппаратный TCB не проверяется самостоятельно Solidity-контрактом |
| Отзыв модели | Проверка реестра до запроса и после завершения инференса; результат отозванной во время вызова модели не публикуется | Квалификация на целевой сети и собственном TEE |
| Версии TCB | Неизменяемые hash/version в ModelRegistry, propose/approve/activate, CAS, восстановление активной политики, отзыв старых сессий и блокировка устаревших записей | Управляет программной политикой; не развёртывает бинарник и не заменяет аппаратную аттестацию |
| USDC и mandates | Авторизованные ERC-3009 переводы, атомарный учёт лимита и комиссий, durable recovery | Реальные адреса/балансы/развёртывание в целевой сети |
| x402 | `/v2/inference`, стандартные HTTP headers и TransferWithAuthorization; официальный SDK, реальные локальные транзакции, восстановление без повторного списания | Только exact EVM/EOA; Circle Nanopayments, Permit2 и smart accounts не реализованы |
| Конфиденциальные суммы | Запрет mock confidential-пути вне локальных chain IDs; API view-key и selective export | Опубликованный рабочий Arc privacy API/контракт и его интеграция; публичные ERC-20 переводы остаются видимыми |
| Agent runtime | Ограниченные многошаговые задания, зашифрованные goal/state/credentials, бюджет, отмена, lease/CAS, журнал действий, восстановление без слепого повтора платного вызова | Аппаратная изоляция runtime/кошелька и выполнение произвольных внешних инструментов |
| Claude Agent SDK | Настоящий MCP-сервер на официальном SDK, четыре инструмента, пример подключения; wrapKey передаётся только доверенному хосту | Хост готовит ciphertext, подписывает оплату и проверяет криптографические доказательства; автономный Claude runtime в TEE отсутствует |
| Economics | Staking, rewards, provider share, 80/10/5/5 и ограниченный router buyback | Рабочий DEX adapter/адреса; правила залогового кредита и slashing не определены ТЗ |
| Производительность | Функциональные и негативные тесты локального стека | Сравнение одинаковой нагрузки на одинаковом GPU с CC/без CC для порога 7%, Blackwell/fine-tuning |

У SDK 100% покрытия функций и инструкций; тесты используют настоящий MCP transport и локальный HTTP, без запуска Claude и платных вызовов. [Описание SDK](../packages/agent-sdk/README.md) содержит его контракт и ограничения.

Полный API/worker integration coverage завершился успешно, все временные контейнеры удалены. Повторный `docker ps` не показал работающих контейнеров. Проверки не меняли обычную базу разработки и её развёртывание контрактов; для x402 v2 нужен новый совместимый UsageMeter с `X402_VERSION() == 2`.

Обновление 20 сентября 2026: проверка итогового набора зависимостей после установки Claude SDK **прошла**. `npm audit --audit-level=moderate` завершился с кодом 0 и результатом `found 0 vulnerabilities`. Предыдущий HTTP 503 был связан с техническими работами npm, завершёнными 19 сентября в 19:00 UTC согласно [официальному статусу](https://status.npmjs.org/). CI сохраняет обязательную проверку audit.

Покрытие относится к включённым в конфигурации исходникам, а не к полноте требований ТЗ. Живой NEAR-сценарий выполнен отдельно от автоматических offline-наборов и использовал один оплачиваемый запрос.

## Эксплуатация разработки

[Инструкция NEAR](near-development.md) описывает установку verifier, запуск, платные проверки и точные границы доверия. Политика `development-glm-2026-09-19.2` действует до **26 сентября 2026, 16:48:57 UTC**. Затем требуется новый просмотр evidence и конфигурации. Автоматического доверия новым VM, устаревшему TCB или изменённым TLS-ключам нет.

NEAR — выбранный провайдер GPU TEE для текущей реализации. Аппаратная изоляция собственного шлюза и агентного runtime остаётся отдельным требованием без обязательной привязки к Phala. Ключ NEAR хранится в игнорируемом `.env.near`; ключи не добавляются в Git и не выводятся в отчёты. Modal остаётся отдельным обычным GPU-профилем для разработки.

Проверка кабинета NEAR 20 сентября: Dedicated deployment открывает форму заявки на мощности; доступа к самостоятельному размещению нашего контейнера не подтверждено. Заявка не отправлялась, ресурсы не заказывались. [Требования к CVM](near-cvm-deployment.md), [управление TCB](tcb-policy-lifecycle.md) и [agent runtime](agent-runtime.md) описывают следующие шаги. Runtime по умолчанию выключен; включение не меняет границы аппаратного доверия.

Docker нужен PostgreSQL, Redis и Anvil в интеграционных тестах, а не NEAR. Тестовый runner создаёт отдельный Compose project, дважды применяет миграцию и удаляет только свои контейнеры/volumes. Сбой Docker во время одного прогона покрытия потребовал повторной проверки; его runtime-каталоги сохранены под именами `*.stale-*`, данные не сбрасывались.

`NODE_ENV=production` продолжает отклоняться. Полное ТЗ нельзя честно пометить выполненным, пока перечисленные аппаратные, сетевые и продуктовые требования не проверены на целевой инфраструктуре.

Для x402 исправлены два найденных риска: присвоение чужого публичного pre-funded разрешения и расход pooled-депозита после reorg funding-блока. Разрешение теперь закрепляется за intent до отправки транзакции и должно быть неиспользованным при приёме; recovery проверяет и события, и calldata, а контракт атомарно проверяет хеш funding-блока. Детали и ограничения: [x402 v2](x402-v2.md).
